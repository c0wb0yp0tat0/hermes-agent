## 1. THE SPA-READ-PATH SPEC

### 1.1 Preserve-at-write: the additive provenance shape (design note)
The contract's backbone is DISCERN's preserve-at-write: every fold appends its timestamp + source, and never rewrites history. The rig's own spa/dream machinery (the compression-saving doc chain, actualized as preserve/rehydrate/prune, plus the dream cycle's consolidation) supplies the shelf. The probes below are written onto that preserved chain:

- **Write (additive, never rewritten):** each new fold of an artifact is appended with a bi-temporal key — `write_ts` (when the fold was added) + `valid_ts` (the as-of line it claims) — and the fold is appended to the chain. Read-side must see the original, unchanged bytes of prior folds. The additive claim is timestamp-fidelity: preserved provenance intact after reads (meter 4).
- **The shelf:** the preserved doc chain (dart + next), the preservation records, and the dream's consolidation surface. The read path lives on those surfaces; no new retrieval machinery is invented.
- **The head pointer:** each fold's preservation record carries a lane head pointer so the chain is navigable as a list of states, one per fold.

### 1.2 Resolve-at-read: zero-LLM navigation (the mechanism adaptation)
The read side of write-gate L0 is designed so the head or any lane reads the preserved states **WITHOUT an LLM retrieval call** — the structured records themselves are the navigation. Concretely:

- `read` walks the chain from the head: fold-3 → fold-2 → fold-1 (rollback), or fold-1 → fold-3 (as-of), by direct record reads, not model inference.
- The read returns the preserved entries; the structured records are the map. No model call for navigation.
- `as-of <valid_ts>` walks the preserved folds to the one whose valid line resolves the point in time (the fold that was current then), and returns that fold's preserved state.
- `entity <artifact-id>` disambiguates WHICH preserved artifact is current when multiple dated folds exist: it picks the fold whose valid line is the latest; if two folds tie for current (the ambiguity case), the conflict is surfaced to the caller rather than silently picked (see §3).

### 1.3 The as-of / entity contrast (design note, rig-adapted from DISCERN's 0.800 entity-resolution shape)
- **as-of** is a point-in-time line: "what was the state at fold-1's valid_ts" → returns fold-1's preserved state.
- **entity** is a "which is current" cardinality: "which dated fold is the current one" → picks the head fold; the 0.800 shape is the disambiguation accuracy of the read when candidates exist.
- The two are different axes: as-of asks "at what time", entity asks "which one is now". The read must do both without an LLM call, the records carrying both the valid line (as-of anchor) and the head pointer (entity anchor).

## 2. THE PROBE SHAPE (the falsifier)

### 2.1 Seed (the experiment)
(a) Seed three preserved states of one artifact — three dated folds of one segment (fold-1 / fold-2 / fold-3), each with its own `write_ts` and `valid_ts`, appended additively. Baseline: fold-1 is current at its date; fold-3 supersedes.

### 2.2 Run (the read path)
(b) Run the read path directly — the probe is executed, not named: (i) direct structured read walks the chain and reveals all three folds without any model call; (ii) `as-of fold-1.valid_ts` returns fold-1's state (the state at a point in time); (iii) `entity artifact-id` resolves the current fold = fold-3.

### 2.3 Measured criteria
(c) The probe's five measured criteria — the falsifier:
1. **Zero-LLM navigation:** all navigation steps (walk fold-1→3, rollback fold-3→1, as-of, entity) complete with **0 model calls** — the zero-LLM claim.
2. **As-of precision:** the as-of query returns the correct state per point in time (fold-1, not fold-3).
3. **Entity precision:** the current fold is resolved = fold-3 (the head), not a stale fold.
4. **Timestamp-fidelity:** preserved provenance unchanged after reads (the additive claim — reads return originals, never rewritten).
5. **Run record:** the execution landed; otherwise `[ABSENT]` for the row.

### 2.4 The FLAG condition (stated before the run)
(d) The probe **FAILS and is FLAGGED** if any navigation step needs an LLM call, or the as-of/entity resolution returns the wrong state. The zero-LLM claim is then falsified for this probe; the design note stands (banner below) and the alternatives are named — never forced. The FLAG line must read when the execution lands.

## 3. THE AS-OF / ENTITY CONTRAST TERM (the term)
The read distinguishes the two axes by the bi-temporal keys on each preserved fold:
- `write_ts` — when the fold was added (provenance/time of the additive write).
- `valid_ts` — the as-of line the fold claims (point-in-time anchor).
- **Current-state marker:** the head pointer on the fold's preservation record — the fold that is current.
- **The ambiguity case:** two folds claim current (a tie on the head pointer / on the valid line). The read **surfaces the conflict to the caller** — it does not silently pick one. That case is the only candidate for the hybrid fallback named below (LLM only for the ambiguity), the 0.800 score's boundary: disambiguation accuracy is the metric, and the zero-LLM claim is about the unambiguous chain walk.
