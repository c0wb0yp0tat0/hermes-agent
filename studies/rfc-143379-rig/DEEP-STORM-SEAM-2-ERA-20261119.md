# DEEP-STORM-SEAM-2 — the window era: why bigger context does NOT retire the substrate, 2026-11-19

*The doubling-down on CTO-FREEDOM-HARVEST seam-2. The first pass found the horizon law; this pass goes to the mechanism beneath it — what actually causes context rot, what the frontier itself says about context engineering, and the serving-cost reality check. The verdict is stronger than before: the covenant of the substrate is not shrinking with window sizes; it is deepening.*

## The findings

**F2.1 — CONTEXT ROT IS A COMPETITION PROBLEM, NOT A LENGTH PROBLEM (arXiv 2611.04169, "Length Is Cheap, Competition Is Not"):** the field's cleanest mechanistic result yet: in retrieval, neutral filler costs nothing — accuracy stays 0.97–1.00 up to 32K tokens; but statements in the FORMAT of the evidence drop it to 0.11–0.21; a single rival-value statement multiplies the loss 9–110×; every additional rival adds to it. **Attention mass left on the evidence explains up to 58% of loss variance; log length explains at most 8%.** The masked-filler protocol behind the "length hurts" claim is shown to have failed a visible control (masking costs 46 points; the same filler visible costs none). The prescription: **"Curate, do not truncate"** — "deduplicating and resolving conflicting statements before they reach the model should matter more than shortening the context." Translation: this is the RFC's governed compaction given its mechanism: the K-recency hard window + provenance-origin + archive-before-stub IS curation-by-state, and the paper's measured law (competition kills, length doesn't) is the load-bearing evidence for archive-before-stub — the store must remove the *competing* statements, not merely shorten the tail. The probe's task design should include the rival-value class (the paper's 9–110× multiplier is the −92.5-point class's mechanism in miniature).

**F2.2 — ANTHROPIC'S OWN CONTEXT ENGINEERING LISTS THE SUBSTRATE'S SHAPES AS THE TOP THREE LEVERS (anthropic.com/research/effective-context-engineering-for-ai-agents):** "Waiting for larger context windows might seem like an obvious tactic. But it's likely that for the foreseeable future, context windows of all sizes will be subject to context pollution and information relevance concerns." Their three techniques: **compaction** ("the first lever"; Claude Code's implementation preserves architectural decisions, unresolved bugs, implementation details — the RFC's archive-before-stub class), **structured note-taking / agentic memory** ("notes persisted to memory outside of the context window... pulled back in at later times... like Claude Code creating a to-do list, or your custom agent maintaining a NOTES.md file" — the doc-chain itself, in the frontier's own words), and **sub-agent architectures** (specialized agents returning condensed 1,000–2,000-token summaries — the swap-and-enrich lane shape). Translation: the study's three movements (governed compaction, doc-chain notes, lane fan-out) are the frontier's own enumerated kit. The era question is answered by the lab that sells the biggest windows: windows of all sizes stay polluted; the levers are the substrate's shapes.

**F2.3 — THE READER-DEPENDENT HORIZON, FULLY READ (arXiv 2611.02361):** the decisive law, now with all the mechanics: models reading full logs fall 72–86% (16 events) → 48–55% (256); a 120B reasoning model trails state by 4–10 points at 256–1,024 events; the operational horizon "grows with the reader" — gpt-oss-120b's horizon is ~1,024 events — meaning stronger readers push the crossover out but never remove it; **state beats the log by +0.12 at one-twentieth the tokens.** The failures are asymmetric and brutal: "prohibitions survive, reinstatements do not" (the restore family refuses 11–15 of 19 valid grants at 64 events — the READ-RESTORE CLASS ITSELF: agents forget the grant and refuse what was already allowed). And the two killer findings for the design: (a) the model-kept ledger fails at chance after 256 events — "the writer drops components it judges inactive and a dropped component never returns" (the RFC's archive-before-stub: something never returns if it is dropped rather than archived); (b) the winning design is the filter that "selects by the state's dependencies when it writes, before any query is known" — write-time curation beats query-time retrieval (the scribe's write-time assert + the doc-chain's write-time discipline, field-proven). Translation: every one of the RFC's controversial pieces (archive-before-stub, the K-recency hard window, the read-restore, the write-time governance) is the measured winning design in this paper.

**F2.4 — THE SERVING-COST REALITY: BREAK-EVEN IS LUMPY, THE SUBSTRATE'S CLASS QUALIFIES (arXiv 2608.11879, "Total Recall at What Cost"; arXiv 2603.04814):** the serving-cost benchmark (400-turn conversations): a memory system's cost "cannot be predicted from conversation length" — driven by internal memory behavior; break-even spans "the first tens of turns for the cheapest to NEVER within 400 turns for the most expensive" (Mem0 at turn 82, Hindsight at 356, Mastra at 0); by 400 turns the full transcript costs up to **12.7× a broken-even memory system**; no system wins on both axes (accuracy 21–54%). The cost-crossover paper (2603.04814): at 100K context, memory becomes cheaper after ~10 turns, break-even N decreasing (13→9) as context grows to 500K; memory saves ~26% by turn 20. Translation: the ECONOMIC answer to "why not just resend the whole window" is now fully measured — the full-transcript strategy is 12.7× at the session lengths the rig actually runs (the 799× marathon, the 22-hour runs, the 300-cycle probes). The substrate's era is not ended by window growth; window growth RAISES the full-resend cost per turn, which is the substrate's own cost curve.

**F2.5 — THE SYNTHESIS'S ONE-PAGE ANSWER (the survey layer):** the field's survey layer (arXiv 2610.21165, memory-centric compression; arXiv 2503.17407, long-context survey; the attention-mechanism survey 2609.39661: "a longer nominal context window does not by itself ensure reliable use of distant evidence — an expanding candidate set can increase retrieval interference") is unanimous on the mechanism: nominal length ≠ usable length; retrieval interference grows with the candidate set; selective state is the remedy. The horizon is a measured property of readers; the cost curve is structural; the frontier's own engineering list is the substrate's shapes.

## The refinement (what this changes for the scramble)
- The era question is settled field-wide, with the mechanism: length is cheap, competition is not — curation (not truncation) is the remedy, and the RFC's compaction governance is curation-by-state.
- The read-restore's class has a name in the wild: the "prohibitions survive, reinstatements do not" asymmetry — agents refusing already-valid grants because the re-confirming event decayed. The RFC's "you're not listening" is this measured asymmetry in human terms.
- The probe's design gains two new arms from this pass: the rival-value/distractor class (F2.1's 9–110× multiplier — the −92.5 class's mechanism) and the write-time-selection assertion (F2.3's filter-beats-retrieval result — the probe should compare write-gated substrate vs query-time-only retrieval at equal state size).
- The economics argument for the RFC gets its numbers: 12.7× full-transcript penalty at 400 turns, break-even ~10 turns at 100K — the study's cost line, field-measured.
