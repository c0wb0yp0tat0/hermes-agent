## THE MECHANISMS UNDERNEATH (the deep dive — how, why, what generalizes, our seam)
*The field's shipped forms are instances of mechanisms. The extraction is the mechanism; the surface stays theirs.*
1. **CAS rewrite (their optimistic-concurrency consolidation) — HOW:** the memory rewrite is a transaction: capture the file's pre-image hash → transform → verify the hash unchanged → atomic rename; mismatch aborts to append-only. WHY: the write's validity is its snapshot's currency — a stale-snapshot write is a lost update, and the hash check is the cheapest detector of "someone else moved the floor." Generalizes: ANY derived-file rewrite becomes a compare-and-swap (the writer's pre-image is the lock's stand-in). OUR SEAM — the memory tool's batch ops + the chain's folds + the anchor-diff-check's comparator: the write-side twin. Two-way: additive pre-image check, revertible.
2. **Supersession keys (their retired-entry marking) — HOW:** an entry's retirement records the KEY of the entry that replaced it — death is a pointer to succession, not a deletion. WHY: append-only keeps the bytes, deletion loses the causality; the succession key makes "what replaced what" reconstructible, so consolidation can merge without erasing lineage. Generalizes: every compaction/review pass can be a versioned ledger instead of a rewrite. OUR SEAM — the chain's UPDATE lines (formalize: each UPDATE names its superseded anchor) + the memory-full push-down protocol. Two-way: additive key field, revertible.
3. **Smallest-writer cap (their bootstrap budget limit) — HOW:** the per-file promotion cap is the MINIMUM bootstrap limit among sharing writers; an oversized rewrite degrades to append-only, never truncation. WHY: a shared resource's invariant must be enforceable by its smallest consumer — one writer's bloat can never starve or overwrite the resource; the degrade path (append) is the zero-risk floor. Generalizes: ANY shared-budget writer set (memory caps, disk guards, fair-share envelopes). OUR SEAM — the MEMORY.md 2,200-char cap's overflow path (currently reject-or-free): degrade to append-downstream instead of byte-squeezing. Two-way: the degrade is the rollback.
4. **Membership gate before scoring (their structural untrusted exclusion) — HOW:** trust is decided at INGESTION by provenance class (owner turn? network-tainted? hash-matched?), and untrusted candidates are excluded by set-membership BEFORE any score is computed — a precondition, never a penalty. WHY: every score-based gate is gameable by accumulation (post enough, the frequency wins); a class test is immune — no amount of recall can promote an entry whose class is excluded. Generalizes: trust gates must be membership predicates first, scoring second. OUR SEAM — the read-gate's admission filter + the harness's honest-rejection threshold: origin-class membership before cosine score. Two-way: the class file is additive, revertible.
5. **Pending-writes registry (their reservation-settlement pair) — HOW:** a capture registers its intent (file, slug) before yielding and settles after the write lands; recovery sees pending entries and drains them. WHY: yields are the crash surface — a write that dies mid-yield is silent unless the intent itself was recorded; the registry turns the yield-race into a recoverable ledger. Generalizes: ANY capture-before-yield discipline (the pre-side/post-side split) becomes mechanized: the pre-side IS the registration, the post-side IS the settlement. OUR SEAM — the compression hook's fold-vs-capture race: register the fold's append before the yield, settle (or drain) on the new context's first read. Two-way: the registry is additive, drainable.
