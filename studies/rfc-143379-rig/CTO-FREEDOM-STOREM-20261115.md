## THE FINDING — the class is known, named, and field-documented

1. **The double-encoded JSON signature is a NAMED frontier failure.** LiveKit (agents PR #5409): Nova Sonic intermittently double-encodes tool-call arguments as a JSON string inside a JSON string → `TypeError: string indices must be integers, not 'str'` — the EXACT error our Nemo ride hit at round 39 ("string indices must be integers, not 'str'"). Their fix: a defensive unwrap loop (`from_json` until the result is no longer a string), non-dict fallbacks raising clean errors surfaced back to the model as a `ToolError`. Goose (PR #10230): GLM/Minimax emit dotted namespaces + double-encoded args + markdown fences → their parser now unwraps, in order and ONLY after a direct parse fails: fences → XML-ish tags → double-encoded JSON (up to two levels, only when an object emerges). Conservativeness locked by tests: well-formed args never enter the unwrap path; truncation stays an error; bare non-object JSON preserves the "must be an object" error.
2. **The schema-root cause is equally named.** Copperhead (PR #236): the provider's tool schema declared `arguments` as `{type: 'string'}` — which FORCES the model to double-encode (a JSON object serialized into a string inside the structured-output envelope). Structured output validated the envelope but not the string's contents. Their root fix: declare arguments as `{type: 'object'}`; plus lenient parsing; plus **failure isolation** — a parse error returns as a tool-level nudge the model can see, never an uncaught abort; plus **deterministic parse-error classification** — a parse/schema error that reproduces across attempts aborts immediately, never wasted on a transient-retry cycle.
3. **The "one repair pass isn't enough" doctrine** (productionnotes.dev): the failure modes are DIFFERENT classes (trailing prose / truncation / fences / double-encoding / semantic garbage that parses) — layered repair points, repair BEFORE validation, validation never removed (it produces structured errors models learn from), original + repaired forms logged for audit.
4. **The validate-before-dispatch envelope** (agentic-pulse.dev + everruns + tinyagents): size/nesting limits before parsing; accept only the documented envelope; tool names from the allowlist; strict-JSON parse then validate against the EXACT schema sent for that tool (required fields, types, allowed values, extra fields); parsing and schema validity do NOT authorize side effects; reject without dispatching, bounded retry, logged failure category. TinyAgents: fail-closed — malformed args are NOT replaced with empty defaults for side-effecting tools; unparseable → transport-level defect with always-on recovery (the parse reason injected back to the model as an error tool result) — a malformed argument blob can never become a never-resolving tool call that stalls the loop.
5. **The unrecoverability insight** (ToolPRM arXiv 2510.14703 + dotttxt): structured outputs are BRITTLE — early JSON errors are functionally unrecoverable; self-reflection gives only minor gains; post-hoc repair is limited; retries for small models top out near 0-30% success and burn tokens. The implication: the TRANSPORT must handle emission defects (the harness's parser), never the lane's hope of fixing itself. "Explore more but retain less" — beam width for candidates, aggressive pruning of retained candidates — validates the write-window's read-gate (drop the reads, keep the write).
6. **The verification-aware wrapper** (arXiv 2608.02645): postcondition verification + verify-before-retry + idempotency keys for NON-ATOMIC failures (timeout-after-dispatch, delayed visibility, partial success, stale conflicts) — the rig's sentinel + branch-head-movement landing gate IS this shape, already live.
7. **SAAG's cascade** (arXiv 2607.18245): registry conformance → structural completeness → argument grounding; argument grounding is THE dominant failure mode (name accuracy near ceiling, argument accuracy lags); structured feedback reduces value hallucination (up to 40% VHR reduction) — stage-specific correction signals beat binary "wrong, try again".

## THE STEERS (the next hardening pass, G15+)

1. **THE DOUBLE-ENCODE UNWRAP (write_file/read_file args)** — the livekit loop, harness-shaped: when a tool call's args parse fails, retry `json.loads` up to two levels; if an object emerges, dispatch with it; log `[EMISSION-REPAIR]` + the original bytes. Direct-parse-first, conservativeness preserved (a bare string that is not a JSON-encoded object stays an error). This kills the Nemo round-39 class at the transport.
2. **THE API-ERROR ISOLATION (the 400/429 kill)** — copperhead-shaped: an HTTPError (400 protocol, 429 rate-limit) returns INTO the lane as a tool-level result it can see and respond to, never an uncaught abort that kills the ride; deterministic parse/schema errors reproduce → immediate abort verdict (no wasted transient-retry).
3. **THE SCHEMA-VALIDATED DISPATCH** — everruns + SAAG-shaped: the harness's tool registry validates each parsed call against its declared schema (required, types, extra fields) before dispatch, returning a structured `invalid_tool_arguments` error with the instance path to the model — the missing chimney between "parses" and "dispatches".
4. **THE BOUNDED-RETRY ENVELOPE** — dotttxt-shaped: retry only the transport-recoverable classes (429 with retry_after respected, transient network); never retry a deterministic emission defect on the same lane — the re-fire is a NEW brief with the receipt of the previous failure (the day's pattern, confirmed by the field: retries don't fix emissions).
5. **THE CONSERVATIVENESS TEST SET** — goose-shaped: for each repair (unwrap, strict-pair, relative-path), the guards are LOCKED BY TESTS — well-formed inputs never enter the repair path, truncation stays an error, and the failure categories are logged by class. The harness's current tests ride the smoke-cert; the emission-repair cases join it.
