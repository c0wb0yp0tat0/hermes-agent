## 3. §1-BIS: THE CLASS SCHEMA'S STRESS

§1 landed with four schema classes. The 66 rows of part B do not exhaust the
schema's four named classes; they *stress* it toward the edges:

1. **`memory-profile`** — named by §1. Part B rows that report a profile span
   whose payload is a *delta* (how much the profile moved, not how big the
   profile is) or a profile bound by a *quota* rather than by volume or by the
   event's raw length. Four of the seven blocks contain a `memory-profile` row
   whose summary describes a profile boundary/delta rather than plain volume.

2. **`user-profile`** — named by §1. Part B rows that report a participant,
   consumer, or agent attribute span that the gate or the rewrite selects on,
   that the read side verifies, or that the bank reads. In the block structure
   this appears in every block, alternating with the two classmates.

3. **`lore/alias`** — new class the bytes demand. §1 did not carry an alias/lore
   class. Part B rows that report a *name/span/alias/label* that the payload is
   the mapping of, the unmapping of, or the pointer of — i.e. a span whose
   meaning the bytes alone would not answer, so the alias is the payload and the
   record is a lookup. These rows have no schema home in §1, so the schema must
   grow a `lore/alias` span class. The class is present in every block of part B.

4. **`memory-delta`/`user-gateway` spans** — the block structure also reveals
   that the row's summary is always a profile-span (of a profile the bank
   reads) plus an alias/span (a pointer) plus a consumer/participant attribute
   (the gate's selection). The strict schema in §1 was written for one lane's
   window and did not anticipate the rotation of classmates seen here; the
   ledger therefore maps each row to the closest §1 class while naming the new
   `lore/alias` class for the alias rows.

The schema grows: §1's four classes remain the core, but part B requires a
`memory-profile` (delta/quota-bearing), `user-profile` (participant/consumer
attribute), and `lore/alias` (name/pointer/label) span classes. The alias class
is the new class the bytes demand and the one most likely to be FLAGged if
a row's own summary is read again after the write; rows 70, 73, 76, 79, 82,
85, 89, 92, 95, 99, 102, 105, 109, 112, 115, 119, 122, 125, 129, 132 are the
alias rows and are accepted by their own summaries.
