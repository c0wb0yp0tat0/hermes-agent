## 3. THE TWO-WAY DOORS FOR THE PILOT

The operator's note (verbatim spine): "the whole mission concept is in itself a two way doors"; the writer's-block technique being reverse-engineered — **the technique generates the doors when the block stares**. Each door: shape (what opens/closes/reverses) · the reversibility test (the concrete undo) · the stake if it were not a door · why it does not corner us.

**DOOR 1 — THE READ DOOR (the spine's door).** Shape: read-path **present ⇄ absent**; the restore opens, the removal closes. Reversibility test: the concrete undo = re-add the ~12-line `MemoryStore.read` (the restore) ⇄ re-delete (56ee8a5cc6's fourteen-line deletion, Feb); neither is a one-way burn — the code is small, the sites are five named files, and the reproduction (6/6 fabrication, 12/12 refusal) is the meter in both directions. Stake if not a door: a read-path load-bearing only once would corner the substrate at the first correction; it is not — the read is idempotent. Why it does not corner us: both states are operable; the label follows whichever state the body is in.

**DOOR 2 — THE LABEL DOOR.** Shape: **label follows body ⇄ body follows label**. Reversibility test: the concrete undo = move the label back — the label-trail itself (six moves without substance change, 34 comments, the 79-minute gap) is the proof the door swings both ways; the meter = the queue buckets re-derive after each move. Stake if not a door: a label pinned forever would corner the triage; the trail shows it is not pinned. Why it does not corner us: the label is metadata, not the body; the body (the read) carries the truth.

**DOOR 3 — THE MISSION DOOR (the whole concept).** Shape: the mission **continues ⇄ folds into the pilot**. Reversibility test: the concrete undo = the pilot's rings are the mission's rings; if the pilot closes, the mission's mechanisms stay — the kit, the register, and the doors are portable, and the mechanism-of-mechanisms package is provider-neutral by design (its own boundary: "no mechanism proven from source docs alone"). Stake if not a door: a one-way mission would burn the study if the pilot failed; it does not — the study's artifacts are the mission's receipts, reversible into the record. Why it does not corner us: the concept's own discipline (receipts, never claims; ABSENT stays ABSENT) is the undo.

**DOOR 4 — THE BLOCK DOOR (from the writer's-block technique).** Shape: the block **stares ⇄ the block generates doors**. Reversibility test: the concrete undo = the technique's output is regenerated each time the block is stared at — the four doors above were generated by staring at the block (the read's absence); the meter = doors-per-block (this artifact: 4 from one block). Stake if not a door: if the block were a wall, the lane would stall; the technique makes it a door-generator. Why it does not corner us: the block's stare is the trigger, not the terminator — the technique converts every block into a door, so no block can pin the pilot.

**DOOR 5 — THE COMPENSATION DOOR (idealization's own door).** Shape: **compensation ON ⇄ read ON**. Reversibility test: the concrete undo = the stack's rows fold back into workaround prose if the read ever regresses — the compensation is the read's shadow, not its replacement; the meter = the fabrication rate, which must go to zero when the read returns. Stake if not a door: a permanent compensation stack would corner the substrate into the user-as-store; it does not — the stack idealizes INTO the read. Why it does not corner us: the stack's retirement is itself a landing, so idealization is a door, not a destination.
