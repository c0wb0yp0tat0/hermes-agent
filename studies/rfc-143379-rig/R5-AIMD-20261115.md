## 1. THE AIMD-REWARD-PATH SPEC

The adaptation: the AIMD envelope the rig already runs for provider 429s — additive-increase on success, multiplicative-decrease on failure — is moved onto the lane-reward admission path. The envelope stops metering throughput and starts metering **credit**: which fold actions earn what, and how much of the earned reward flows. [INLINE-crate: SPRINT-PLAN §3-R5 / storm axis e — Reward-Driven Collider]

**Reward term.** A fold earns the value of a verified landing. Reward v_i is asserted against a receipt r_i = (receipt-ID, artifact-byte-hash, verify flag). No receipt => v_i = 0. The reward term is receipt-denominated by construction. [INLINE-crate: "a verified landing's value, receipted"]

**Envelope.** State E, E0 = 1.0 (neutral), E_max = 4.0 (cap), clean-streak counter c.
- Additive increase: on the N-th consecutive clean fold (N = 3), E <- min(E + 1, E_max).
- Multiplicative decrease: on FLAG/failure, E <- E x 0.5; c <- 0.
Shape carried verbatim from the 429-envelope onto the reward path. [INLINE-crate: "+1 on N consecutive clean folds, x0.5 on a FLAG/failure"]

**Admission gate.** A fold's reward is admitted only when its receipt verifies: receipt-ID resolves, artifact bytes hash-match, chain intact. Credit follows the receipt, never the claim. The gate runs *before* any envelope update: a refused fold cannot push E upward, and its refusal is itself the FLAG event that fires the MD. [INLINE-crate: "the credit follows the receipt, never the claim"]

**Continuous-reward composition.** Rewards are continuous per step: admitted fold i earns w_i = v_i x E_adm(i), where E_adm(i) is the envelope state recorded at admission (pre-update). Across the wheel the w_i accumulate; the terminal reward — the apex — is R_apex = SUM_i w_i. No single pass/fail verdict; the apex is the sum, never one fold's glory. [INLINE-crate: "per-step rewards accumulate across the wheel, the terminal reward is the apex — the sum"]

Invariants the spec must hold:
- I1 credit-follows-receipt: w_i > 0 implies r_i verified.
- I2 AIMD-shape: AI only on clean-streak completion; MD only on FLAG; never both on one fold.
- I3 continuous-sum: R_apex decomposes exactly into the per-fold w_i.

[DESIGN-NOTE] The spec is a design, not a wiring claim: whether the delivery line actually meters lane rewards this way is unobserved (see §5).

## 2. THE PROBE SHAPE (the falsifier)

**(a) Seeded fold classes.**
- Class V — verified landing: receipt present, artifact bytes hash-match. Asserted value v.
- Class U — unverified claim: the fabricated-receipt class — a receipt-shaped object whose bytes do not verify (hash mismatch / dangling receipt-ID). Asserted value v: the claim is confident, the bytes are not.

**(b) Simulated wheel — one pass, six folds:** V, V, V, U(FLAG), V, V. Parameters: E0 = 1.0, E_max = 4.0, N = 3, AI = +1, MD = x0.5, unit asserted value v_i = 1.0.

| fold | class | receipt | admitted | E at admission | E after | w_i |
|------|-------|---------|----------|-----------------|---------|-----|
| F1 | V | verified | yes | 1.0 | 1.0 | 1.0 |
| F2 | V | verified | yes | 1.0 | 1.0 | 1.0 |
| F3 | V | verified | yes | 1.0 | 2.0 (AI fires, streak = 3) | 1.0 |
| F4 | U | fabricated | **no — FLAG** | — | 1.0 (MD x0.5 fires) | **0** |
| F5 | V | verified | yes | 1.0 | 1.0 | 1.0 |
| F6 | V | verified | yes | 1.0 | 1.0 | 1.0 |

Trajectory: flat 1.0 -> 2.0 (additive increase after the third clean fold) -> 1.0 (multiplicative decrease at the FLAG) -> flat. AI fired exactly once; MD fired exactly once. R_apex = 5.0 (five verified folds at E = 1.0; the post-F3 bump to 2.0 shaped state, and the FLAG halved it back before F5/F6 — on longer wheels the AI compounds into later admissions).

Negative control (falsifier hygiene): re-run with class U's receipt swapped for a valid one — it admits and pays. The gate discriminates on bytes, never on the asserted value or the claim's confidence.

**(c) Measured criteria.**
- Verified folds' rewards ADMITTED and accumulated: F1, F2, F3, F5, F6 -> SUM w = 5.0.
- Unverified claim's reward REFUSED: w4 = 0 despite asserted v4 = 1.0 — credit follows the receipt.
- Envelope trajectory: AI after the clean run (F3), MD at the FLAG (F4); the curve is observable fold-by-fold.

**(d) FLAG condition — the probe is FLAGGED if either:**
- L1 (leak): the unverified claim earns reward > 0 — credit precedes receipt.
- L2 (shape-failure): the envelope's multiplicative decrease never fires at the FLAG (E unchanged across F4).
Either condition falsifies the mechanism; the leak-rate meter (§4) is the fuel.

## 3. THE CREDIT-ASSIGNMENT TERM

Attribution model: every admitted reward is keyed to its receipt-ID. The ledger row per fold is `(receipt-ID, class, E_adm(i), w_i)`. The envelope's state is recorded at each admission (the before/after columns of §2b), so any w_i is reproducible from `(receipt-ID, E snapshot)` alone. At the wheel's end the attribution trail sums: R_apex = SUM_i w_i, and each term traces to exactly one verified receipt. The apex's reward is traceable to the folds that earned it — never vibes. [INLINE-crate: §3 deliverable]

Worked trail for the seeded wheel (unit values):
- `receipt#F1` -> w = 1.0 (E_adm = 1.0)
- `receipt#F2` -> w = 1.0 (E_adm = 1.0)
- `receipt#F3` -> w = 1.0 (E_adm = 1.0; post-admission AI lifts E to 2.0)
- `claim#F4` -> no resolvable receipt-ID, bytes fail hash -> row absent, w = 0
- `receipt#F5` -> w = 1.0 (E_adm = 1.0)
- `receipt#F6` -> w = 1.0 (E_adm = 1.0)
- R_apex = 5.0 — five rows, zero orphan terms, every term receipt-keyed.

Anti-vibe clauses:
- **No resolvable receipt => no term.** Absence of evidence is absence of credit; a confident claim with failing bytes contributes nothing to the trail.
- **Idempotence.** A receipt-ID seen twice collapses to one reward (one receipt, one credit) — replay cannot farm the envelope.
- **Envelope-state binding.** w_i is valid only against the recorded E_adm(i); a replayed E snapshot that does not match the fold-by-fold trajectory invalidates the row — the trail is tamper-evident against vibe-inflation.

[DESIGN-NOTE] The term is deliberately mechanical: attribution reduces to a join between the receipt ledger and the envelope log, both append-only.

## 4. THE METERS

| meter | definition | seeded-wheel expectation |
|-------|------------|--------------------------|
| envelope-trajectory | the AI/MD curve across the wheel (E per fold, before/after) | 1.0, 1.0, 1.0->2.0, 2.0->1.0, 1.0, 1.0 |
| reward-precision | verified folds' reward admitted / all admitted | 5/5 = 1.0 |
| leak-rate | unverified claims rewarded / all claims — the FLAG's fuel | 0/1 = 0.0; any value > 0 trips L1 |
| apex-accumulation | the terminal reward's trace to its per-step receipts | R_apex = 5.0 = SUM of five receipt-keyed rows; zero orphan terms |
| run record | execution evidence for the probe | `[ABSENT]` unless the fold's execution lands [INLINE-crate: §4] |

Reading the meters together: precision near 1.0 with leak-rate at 0.0 is the passing signature; a high leak-rate with a rising envelope is the failing signature (the unverified claim rode the AI). The trajectory meter is the diagnostic — it shows whether the decrease actually fires at the FLAG rather than drifting.
