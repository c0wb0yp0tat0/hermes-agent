## THE TEST TRACK

**Candidate:** v4-mini-300M slice with the private-repo pattern — selected as the first canary per the Darkhorse weighted criteria (cost-to-test 30%, falsifiability speed 15%, off-rig-disk readiness 20%; `HY5-CTO-PROXY-ACES-20261118.md` §THE DARKHORSE TRACK).

**Off-rig disk route:** the weights' home is the private repo's `releases/LFS`. Nothing is downloaded onto the rig as a standalone kit; the off-rig GitHub disk IS the storage layer. This is the private-repo framework applied by name, innovated-first — the LFS/release path is the disk, not a downloaded-as-is artifact. Receipt: `DARKHORSE-TRACK-1-20261118.md` pins the candidate's HuggingFace sha (`fc8b9934bfdc04adaa7ff7f3f10f48349c72bf64`) and the private-repo pattern as the canonical off-rig home.

**Sandbox:** the 300M test runs in an isolated environment (PVE or Windows host — no host committed yet; open-minded per HY5-CTO-PROXY-ACES). The sandbox touches no rig state and exercises no production seat. Its purpose is the minimal reproducible run that produces a cell-hosted receipt before any further commitment.

**Cell-hosted receipt gate (BEFORE any host/pick commitment):** the receipt is a structured artifact posted to a named cell location containing at minimum:
1. Sandbox environment identifier (host type, isolation boundary).
2. Model sha fingerprint (`fc8b9934bfdc04adaa7ff7f3f10f48349c72bf64` from track-1 receipt).
3. Inference test result: the model loads, runs a minimal forward pass, and produces output deterministically within tolerance.
4. Licensing attestation: the model's weight license is named and confirmed compatible with the private-repo hosting pattern.
5. LFS egress clearance: the private-repo LFS path is confirmed as the sole egress route; no secondary download or redistribution has occurred.

No commitment — no escalation, no host allocation, no weight installation onto the rig — fires until this receipt exists in the named cell.

**Licensing/LFS egress clearance (named, required before reliance):**
- Licensing: the model's declared license must be read and confirmed compatible with the use pattern before the private-repo path is treated as authoritative.
- LFS egress: the LFS path is the only egress route; egress must be confirmed as a one-way store (releases/LFS → sandbox read-only), not a redistribution channel. Clearance is named in the receipt, not assumed.
- Both items are marked "not confirmed" pending the sandbox run; they become receipt claims only after the cell-hosted receipt gate fires.

**Escalation ladder:** 300M → V3-3.4B-small → R1-distills → V2-Lite 16B/2.4B. Each rung is armed only after the previous rung's test gate is fully receipted. The ladder is the Darkhorse track made explicit — it is active (STEER-11: never gated; interest = GO), but each step remains gated by its own receipt, not assumed.

## THE GATE

The gate that must be true before ANY host/pick commitment fires:

**The cell-hosted receipt must exist with all five fields complete:**
1. Sandbox environment identified and isolated (host type, no rig state touched).
2. Model sha fingerprint matches the pinned track-1 sha.
3. Inference test passes: model loads, runs a minimal forward pass, output is deterministic within tolerance.
4. Licensing attestation: model license is named, read, and confirmed compatible.
5. LFS egress clearance: private-repo LFS path confirmed as sole egress, one-way store, no redistribution.

**None of the following fires until the receipt exists:**
- Any host allocation (PVE or Windows).
- Any weight installation onto a production seat.
- Escalation to the next ladder rung.
- Adoption or integration of the model into any rig workflow.

The gate is the receipt, not a vibe. If the sandbox run fails any field, the canary is a falsification — the ladder terminates, the failure is receipted, and the next step is a pivot decision, not a retry.

## THE SUCCESS CRITERION

**Measured success:**
1. The canary's receipted test lands — the cell-hosted receipt exists with all five fields complete.
2. The ladder's next rung (rung 2, V3-3.4B-small) is armed — its test conditions are defined and ready to execute, not merely promised.

**What success is NOT:**
- Success is not the model performing well on benchmarks — it is the receipt existing and the ladder arming.
- Success is not the Darkhorse track being adopted — it is the test track running cleanly enough to arm the next rung.
- A falsification at any rung is a receipted outcome; the canary's job is to produce evidence, not to pass.
