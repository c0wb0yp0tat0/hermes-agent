## 2. THE COMMAND-SURFACE CONTRACT (the three rules as named, usable templates)

**Contract name:** `COMMAND-SURFACE-CONTRACT-20261110`
**Command-surface:** the chat-layer is the command-surface — decisions in, evidence out. The rules below are instantiated so the next run can execute them verbatim.

### 2.1 Rule 1 — the ≤2-line prompt template (one named artifact)

**Prompt-shell (exactly ≤2 lines, one named artifact):**

```
[test] artifact:<NAMED_ARTIFACT_PATH> — <one reversible question, ≤2 lines>
```

- `<NAMED_ARTIFACT_PATH>` is the **only** artifact name the prompt may carry — the artifact the command-surface reads from.
- Example (filled): `artifact:CYCLES/FOLD1-20261110.md — does the fold's compose-check table show DONE for every row?`
- **Gate:** if the prompt is >2 lines, or carries an artifact name other than the one named, the command-surface REJECTS it (parse error, not a failure).

### 2.2 Rule 2 — the evidence-cadence row template (3–5 turn cadence, CHANGED / EVIDENCE / NEXT-BLOCKER)

**Row template (one row per turn, 3–5 turns between full rows):**

| Field | Shape |
|---|---|
| `CHANGED` | `yes` | `no` |
| `EVIDENCE` | `<path>:<line-or-section> — <verbatim quoted claim>` (quoted, never paraphrased) |
| `NEXT-BLOCKER` | `<named gate that stops the fold, or empty>` |

**Example (full cadence, three rows):**

```
CHANGED: no | EVIDENCE: CYCLES/FOLD1-20261110.md §2 — "the gate's closure row: all five receipts on disk" | NEXT-BLOCKER: S3→S4 fold-2 brief (FOLD2-20261110.md)
CHANGED: yes | EVIDENCE: FOLD2-20261110.md written to CYCLES/; 5-part template applied | NEXT-BLOCKER: S4→S5 fold-3 brief
CHANGED: no | EVIDENCE: fold-2's compose-check table all DONE; gate reads the head's tree | NEXT-BLOCKER: (none — next fold arms)
```

- The cadence is **3–5 turns**: a full CHANGED/EVIDENCE/NEXT-BLOCKER row is written every 3–5 turns; a partial row (no CHANGED, or no NEXT-BLOCKER) is a parse error.
- **Gate:** the command-surface verifies the row cadence and the quoted evidence anchor; a row that fails either is logged, not executed.

### 2.3 Rule 3 — the ≤6-line machine-parseable handoff template

**Handoff (per mechanism's HANDOFF-FANOUT, ≤6 lines, machine-parseable; no free text in the machine fields):**

```
[handoff] from:<NAME> to:<NAME> gate:<GATE_NAME> fold:<FOLD_N> artifact:<PATH> trigger:<S_N->S_{N+1} closure>
```

- Fields: `from`, `to`, `gate`, `fold`, `artifact`, `trigger`. All machine-parseable ASCII; ≤6 lines; no prose in these fields.
- `_trigger_** is the **exact gate transition string** (`S3→S4`, `S2→S3`) — the trigger is the gate's closure row, never a clock tick.
- **Gate:** if the handoff is >6 lines, or any machine field is absent/email-free, the handoff is rejected. The transfer of a mechanism is complete only when the next fold's brief is on the head's tree (FOLD{n+1}-YYYYMMDD.md present, `git ls-files` returns it at the branch head).
